# claude-interview-note-writer

一个给 Claude Code 使用的面试笔记整理 Skill，用来按照固定结构整理中文八股文笔记，也可以检查并重写旧笔记中“代码太多、文字太少、结构不像问答”的内容。

它适合这类笔记库：

```text
基础面试题/
  0.目录/
    1.Java基础.md
    2.Java集合.md
    ...
  1.Java基础/
    基本数据类型.md
    String StringBuffer StringBuilder.md
    ...
```

## 解决什么问题

这个 Skill 的重点不是让 AI 随便生成一堆内容，而是约束 AI 按已有笔记风格整理内容：

- 目录文件负责按模块组织知识点，并链接到具体笔记。
- 每个知识点文件都用 `### 问题？` 加回答的结构。
- 第一个问题必须是该知识点最核心、最高频的面试问题。
- 后续问题作为扩展追问，方便像翻书一样快速定位。
- 回答以中文讲解为主，代码只在文字解释不清时少量使用。
- 避免 AI 偷懒写得过短，也避免写成大段代码教程。
- 可以按指定范围检查旧笔记，并把不符合风格的文件改成文字讲解为主的三级标题问答。
- 整理前会优先参考同模块里的优秀笔记，只有缺少同模块样本时才用 Java 基础笔记作为兜底风格参考。

## 安装方式

把本仓库中的 `SKILL.md` 放到 Claude Code 的 skills 目录下，例如：

```text
~/.claude/skills/interview-note-writer/SKILL.md
```

如果是项目级 Skill，也可以放到项目目录：

```text
项目根目录/.claude/skills/interview-note-writer/SKILL.md
```

## 使用方式

在 Claude Code 里可以这样描述任务：

```text
使用 interview-note-writer，帮我整理 Java 集合里的 HashMap 内容，保持我基础面试题的目录和三级标题问答结构。
```

也可以用于已有内容的重写：

```text
使用 interview-note-writer，帮我把这个知识点文件整理得更像 Java 基础里的写法，保留三级标题问题结构，减少无用代码。
```

也可以指定范围检查旧文件：

```text
使用 interview-note-writer，检查 基础面试题/2.Java集合 下面的内容，找出代码太多、文字说明太少、不像面试问答的文件，并直接改好。
```

## 写作规范

知识点文件的基本结构：

```markdown
### 核心问题放在第一位？

这里直接回答最核心的面试答案。

### 常见追问是什么？

这里继续展开追问、边界、场景或坑点。
```

回答风格：

- 定义题可以短而准，不强行扩写。
- 区别题按关键维度对比。
- 原理题讲清核心机制，不无限深入源码。
- 场景题说明什么时候选什么。
- 坑点题说明错误做法和原因。
- 代码只作为辅助解释，不喧宾夺主。
- 不把 `定义/区别`、`底层原理`、`使用场景` 这类思考角度暴露成固定模板小标题。

## 参考样本规则

整理或检查笔记时，优先参考同模块里的优秀文件，学习它们的口吻、密度和问题组织方式。

如果同模块没有合适样本，再参考 Java 基础里的优质文件，例如：

- `基本数据类型.md`
- `String StringBuffer StringBuilder.md`
- `接口和抽象类.md`
- `多态.md`
- `异常处理.md`

Java 样本主要用于学习“回答密度、直接程度、三级标题问答结构”，不要把 Java 特有表达硬套到其他模块。

## 适用范围

主要适合整理 Java、后端、数据库、中间件、AI 应用开发等面试知识点。

如果你的笔记也采用“目录索引 + 知识点文件 + 三级标题问答”的结构，可以直接复用或稍微调整本 Skill。
